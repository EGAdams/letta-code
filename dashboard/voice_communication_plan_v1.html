Project Plans / Canonical Working Plan

Voice Communication

Build a real-time voice system from the useful parts of voice_agent and Pipecat, one tested object boundary at a time.

Active design Started August 1, 2026 Source: talking_agent_parts Method: SOLID + Gang of Four
New leaf rule. Every bug and alteration begins with a SOLID audit. The first design catalog we consult for a remedy is the Gang of Four book. We select a pattern only when it explains the forces and improves the object boundaries; pattern names are not permission to add ceremony.

Decision and boundaries

Pipecat is the real-time media framework. It owns frame flow, transports, turn detection integration, interruption propagation, STT/TTS service plumbing, and pipeline lifecycle.

Our objects own application policy. They decide which agent receives a turn, what may be spoken, how one active run is enforced, how stale output is rejected, what a session means, and how providers are selected at the composition root.

The existing /home/adamsl/voice_agent repository is evidence and a source of adapters. We preserve recordings, settings, environment knowledge, and behavior tests. We do not make the new domain depend on its synchronous orchestrator or concrete provider classes.

SOLID Change Protocol

This protocol is required for every defect, feature request, and refactor in the new system.

  1. Reproduce first. Add the narrowest failing test or characterization test. Record the observed RED result.
  2. Audit all five principles. Name the violated boundary and cite the concrete dependency, responsibility, subtype behavior, or oversized interface that proves it.
  3. Open the GoF catalog. Compare the problem's forces with applicable patterns. Record the selected pattern or explicitly record why no pattern is needed.
  4. Change the smallest object boundary. Prefer moving a decision behind a port, injecting a collaborator, or splitting a responsibility over adding conditionals to an orchestrator.
  5. Run shared contract tests. Every adapter for a port must pass the same behavioral contract. Fakes are first-class adapters for offline tests.
  6. Refactor after GREEN. Remove obsolete branches and duplicated policy. Update this plan when an object, port, or pattern decision changes.
PrincipleQuestion asked before editingRequired evidence
Single Responsibility PrincipleHow many independent reasons can this object change?Name the actors or policies currently mixed together.
Open/Closed PrincipleCan the requested behavior be added through a new implementation?Show whether existing conditionals must be edited for each provider or mode.
Liskov Substitution PrincipleCan every implementation honor the port's preconditions, results, errors, cancellation, and ordering?Run the same contract suite against every adapter.
Interface Segregation PrincipleIs a client forced to depend on methods or events it does not use?List each client and the smallest capability it needs.
Dependency Inversion PrincipleDoes application policy import Pipecat, Faster-Whisper, OpenAI, sounddevice, pyttsx3, or Letta directly?Concrete construction appears only in adapters and the composition root.

Gang of Four First

Use this short list as the first design search, not as a mandate to use every pattern.

PatternUse in this systemForce it resolves
StrategyTurn policy, STT/TTS provider choice, spoken-output policy, retry policy.Algorithms vary independently from the clients using them.
AdapterLettaAgentAdapter, optional legacy Whisper/Moonshine adapters, Pipecat frame bridges.External APIs do not match our application ports.
StateVoiceSession: idle, listening, thinking, speaking, interrupted, closed.Valid behavior depends on lifecycle state and transitions must be explicit.
Factory MethodPipelineFactory creates a configured pipeline from injected provider factories.Construction varies while callers use one creation contract.
Chain of ResponsibilitySpokenOutputPolicy filters reasoning, tool calls, status events, stale generations, and unsafe commands.Independent gates should compose without one giant conditional.
ObserverSession events feed transcripts, metrics, logs, and dashboard status.Telemetry and UI react without coupling into conversation logic.
CommandConfirmed external actions and cancellable agent turns.Requests need identity, validation, execution, cancellation, and audit.

Patterns currently rejected. No global Singleton service locator, no general-purpose event bus before a second real consumer exists, no Abstract Factory until we truly need compatible product families, and no custom frame hierarchy that merely duplicates Pipecat frames.

Dependency rule: domain imports no Pipecat, Letta, OpenAI, Faster-Whisper, sounddevice, pyttsx3, filesystem, network, or dashboard modules. application imports only domain values and ports. Concrete imports are restricted to adapters and composition/bootstrap.py.

Implementation plan

Phase 0 - Baseline and decision records

  1. Record Python and target-host constraints; Pipecat currently requires Python 3.11 or later.
  2. Pin a tested Pipecat version and provider extras in pyproject.toml.
  3. Turn selected recordings in voice_agent/recorded_audio/ into named characterization fixtures with expected transcript intent, not brittle punctuation.
  4. Capture baseline end-of-speech to transcript and first-audio latency on the target machine.
  5. Write ADR-001: Pipecat owns media; our application owns agent/session policy.

Phase 1 - Framework-free objects

  1. Create failing tests for VoiceSession transitions and generation fencing.
  2. Create the smallest immutable domain events required by those tests.
  3. Create IConversationAgent and its fake through shared contract tests.
  4. Create SpokenOutputPolicy as independently tested gates.
  5. Create ConversationCoordinator only after its collaboration tests are RED.

Phase 2 - First Pipecat slice

  1. Build a local browser transport pipeline using Pipecat's standard frames and pipeline lifecycle.
  2. Use Pipecat's built-in WhisperSTTService, which already uses Faster-Whisper for local CPU/CUDA transcription, before writing a custom STT adapter.
  3. Use Silero VAD and a Pipecat user-turn strategy. Compare Smart Turn with a measured speech-timeout strategy; make the choice an injected Strategy.
  4. Use a Pipecat TTS service that produces streamable audio. Keep pyttsx3 out of the first real-time path.
  5. Bridge finalized user turns to the fake conversation agent and prove barge-in suppresses stale output.

Phase 3 - Letta adapter

  1. Write fixture-driven tests from representative Letta streaming events.
  2. Implement LettaAgentAdapter without importing it into domain or application modules.
  3. Separate public assistant text from thoughts, tool calls, tool results, and status events.
  4. Assign every run a generation identity; cancel when supported and always fence late events.
  5. Prove voice and dashboard text routes reach the same Letta agent memory and tools.

Phase 4 - Reliability and provider substitution

  1. Run shared STT/TTS/agent contracts against every enabled adapter.
  2. Add Pipecat service switching only after a real primary/fallback requirement exists.
  3. Add Observer-based structured logs and latency metrics without coordinator edits.
  4. Test disconnect, reconnect, timeout, cancellation, no-speech, and provider failure.
  5. Benchmark local Whisper on the actual host and set measured P99 latency rather than relying on a generic default.

Phase 5 - Dashboard integration

  1. Add a dashboard host adapter around VoiceCommunicationApplication.
  2. Reuse the existing agent selector and show listening, thinking, tool-working, speaking, interrupted, and failed states.
  3. Keep browser-specific code behind the dashboard's established abstract/implementation interfaces and injected HTTP/timer collaborators.
  4. Require explicit confirmation before destructive or externally visible Commands execute from voice.
  5. Deploy only after browser, Android secure-context, and interruption acceptance tests pass.

Definition of done for the first vertical slice

  • A browser user completes ten turns with one selected Letta agent.
  • The user can interrupt speech; no token or audio from the old generation is heard afterward.
  • Tool calls execute through Letta, but thoughts, tool calls, tool results, and status events are never spoken.
  • Switching between fake and Letta conversation adapters changes only composition wiring.
  • Switching supported STT or TTS implementations changes only composition wiring.
  • Domain and application dependency rules are enforced by an automated test.
  • All adapters pass their shared contract suites.
  • Latency is measured from end-of-speech to finalized transcript and from finalized transcript to first output audio.
  • Every implemented object points back to a failing test and a recorded SOLID/GoF decision card.

Immediate next slice

Create only three production objects first: VoiceSession, a fake-backed IConversationAgent, and ConversationCoordinator. Build their tests without Pipecat. Once generation fencing and one-run-at-a-time semantics are correct, add PipelineFactory as the first Pipecat adapter boundary.
