correctly failed closed instead of guessing a year or falling back to receipt/statement

`wrap-v054`, which adds a learned rule to normalize `MM/DD` scheduled dates before
reconciliation and still fail closed if normalization is ambiguous. That's a good, in-scope
improvement, but it can't fix the underlying Python `ValueError` in the reconciler script
itself — a code fix (accept `MM/DD` and infer year from context, e.g. nearest year not in
the future) is needed in `moms_ledger_reconciler.py` for future runs to actually succeed
past this point.
