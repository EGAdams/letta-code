## Diagnosis

This is **not a wrapper defect**. Mazda classified, parsed, checked vendor key, categorized, and
attempted to store correctly. Both failures are the live finance database missing columns that
the `check_duplicates` and `parse_and_categorize.py --save` code paths already assume exist:
`expenses.expense_role` and `expenses.account_number`.

**This should not still be happening.** Project memory
(`expense_role_column_missing_and_scanner_lock_2026_07_25`) records that the
`expense_role` migration (`tools/itemization/migrations/001_expense_roles.sql`) was applied
earlier today and confirmed present via `information_schema.COLUMNS`. This run, ~hours later,
hit the exact same `expense_role` error again, plus a **new** missing column,
`account_number`, on the save path. Two possibilities: (a) the earlier migration didn't
actually persist / was applied to a different DB instance than the one this run's connection
pool is using, or (b) there is a second, still-unapplied migration for `account_number`
(possibly a related itemization/account-linking migration). Either way this needs a human
(EG) to check `information_schema.COLUMNS` on the live `expenses` table directly and confirm
which migrations are actually applied there.
