## Wrapper defect or application defect? (Step 0 classification)

**Application defect.** Chapter 5 of Mazda's manual states the intake judge is
"deterministic-rules-first": a rule-based evaluator scores structured evidence into a verdict
before any LLM judge is consulted. That Python evaluator has no `doc_kind=tax_document` branch, so
it unconditionally checks `vendor_key_resolved`/`category_resolved`/`duplicate_check_ran`/
`expense_stored` regardless of document type. Wrapper "instructions" text (the prose rules
`load_wrapper_revision` returns) is never parsed or executed by that evaluator — it is read only by
Mazda's own LLM reasoning. So "activating" Rule 57/Rule 100 via `apply_proposal` changed what
Mazda is told to do, but could never change what the deterministic judge checks. Fixing this
requires editing the evaluator/judge source, not another wrapper proposal.
