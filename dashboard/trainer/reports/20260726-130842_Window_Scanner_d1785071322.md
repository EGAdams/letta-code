## Wrapper defect diagnosed

Mazda's statement-report step wrote `report.html` next to the scratch scan file
(`tools/receipt_scanning_tools/incoming_scans/report.html`) instead of the archived
statement directory returned in `archive_paths`
(`readable_documents/bank_statements/2025/february/diners_club_international_4887_february_28__march_17/`).
This is exactly the historical incident documented in
`tools/python_tasks/verification_lib/REPORT_OUTPUT_CONTRACT.md` — the dashboard hard-codes
`<statement_dir>/report.html`, so any other location renders a blank report tab. Nothing in
the dispatch or wrapper instructions currently anchors the report target to the archive
path returned by the store step, so this is a real, recurring gap — it produced content
that passed every content-level check while still being invisible to the dashboard.
