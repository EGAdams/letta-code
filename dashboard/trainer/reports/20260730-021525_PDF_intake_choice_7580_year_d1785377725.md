## Wrapper defect identified (this is a real bug, not a model failure)

`store_statement_transactions.py`'s credit/debit sign-convention logic is undocumented/unenforced for callers: it silently treats sign as authoritative and drops rows it decides are "credits" with `ok:true`, rather than rejecting on an internal consistency mismatch (e.g., a `debit_credit` field disagreeing with the sign it infers). Because no dedicated parser exists for workbook/Excel statement exports, any ad-hoc parse is exposed to this landmine. Proposal 208 / memory note 209 correctly target this; a maintainer should also consider making `store_statement_transactions.py` itself refuse (rather than silently skip) when it discards >X% of parsed rows as credits, so this class of bug fails loudly even without a sharp-eyed Trainer catching it.
