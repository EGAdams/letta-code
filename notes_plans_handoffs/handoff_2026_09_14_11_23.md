## What I tried, and what's still broken

**Attempt 1 — enable pooling (Option A from the report).** Added to
`~/letta-src/docker-compose.prod.yml` on 100.80.49.10 (the `letta` service's `environment:`):
```yaml
LETTA_DISABLE_SQLALCHEMY_POOLING: "false"
LETTA_PG_POOL_SIZE: "20"
LETTA_PG_MAX_OVERFLOW: "5"
```
Redeployed via `cd ~/letta-src && docker compose -f docker-compose.prod.yml up -d letta`
(use `docker compose`, the v2 plugin — the old `docker-compose` v1 binary on this box throws
`KeyError: 'ContainerConfig'` on recreate against buildkit-built images).

**This exposed a second, previously-dormant bug.** `letta/server/db.py` only adds
`connect_args={"ssl": "require"}` for asyncpg when pooling is **enabled**
(`if not settings.disable_sqlalchemy_pooling: ...`) — so it was never hit while NullPool was
active. The embedded local Postgres in this container doesn't support SSL, so the app crashed
at startup: `ConnectionError: PostgreSQL server at "localhost:5432" rejected SSL upgrade`, then
a secondary `RuntimeError: generator didn't stop after athrow()` inside
`DatabaseRegistry.async_session()` in `db.py` (worth flagging to Suzuki separately as a real
exception-handling defect in that async context manager — it should not be possible for an
underlying connection error to produce an unrelated `RuntimeError` on generator close).

**Attempt 2 — disable SSL via `LETTA_PG_URI`.** Tried
`?sslmode=disable` first — wrong: `letta/database_utils.py`'s `convert_to_sync_uri()` /
`convert_to_async_uri()` do a **naive string replace** between `ssl=` and `sslmode=`, and the
*canonical* form is expected to use `ssl=`, not `sslmode=`. `sslmode=` broke the **sync/alembic**
migration path instead (pg8000's `connect()` doesn't accept an `sslmode` kwarg at all →
`TypeError: connect() got an unexpected keyword argument 'sslmode'` → migration fails on every
boot → crash loop, saw the container hit **25 restarts** before I caught it).

Corrected to `?ssl=disable` and redeployed — **this was still crash-looping with the exact same
`sslmode` TypeError when I was interrupted for shift change.** I had NOT yet root-caused why —
possible leads for next shift, not yet checked:
- Read `/home/adamsl/letta-src/alembic/env.py` directly (it's mounted read-only in
  `frita-executor` now, so an Opus/Sonnet agent can grep it) around line 83
  (`connectable.connect()`) — check how `connectable` is actually constructed earlier in that
  file. The traceback goes straight from alembic's `env.py` into SQLAlchemy's pool code; it's
  not confirmed whether `env.py` even calls `get_database_uri_for_context()` at all, or builds
  its own engine URL separately (which would explain why the `ssl=` vs `sslmode=` fix in
  `LETTA_PG_URI` didn't propagate).
- Double-check the env var actually took effect inside the container on the 2nd attempt
  (`docker exec letta-server env | grep LETTA_PG_URI`) — I confirmed this on attempt 1 but not
  after the `ssl=disable` correction, so it's possible a stale value or a compose caching quirk
  was in play, not the code itself.
