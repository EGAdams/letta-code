Cutting server.py in Half

dashboard/server.py started at 11,407 lines. The goal is to halve it (≤ ~5,700) by extracting cohesive, low-coupling clusters into their own modules, typed with Pydantic where a wrong value would otherwise fail silently, each extraction backed by its own tests.

Where the typing earned its keep

CodexUsage / ClaudeUsage — the all-clear that meant nothing. Round 8's note said to look for the Pydantic target in the probe responses, not the caches, and to check first whether a malformed body currently yields a confident verdict. It does. Both classifiers read the payload as a bag of optional keys: 

rl = usage.get('rate_limit') or {}        # codex
w  = usage.get('five_hour') or {}         # claude
pct = float(w.get('used_percent') or 0)

So a body whose shape had moved — a renamed key, an error envelope, a login page — produced no windows, no limit_reached, and therefore a clean pass:

payloadold behaviournew behaviour
{'detail': 'Unauthorized'}→ {'ok': True, 'text': ''}refused: the usage block: Field required
{'rate_limit': {}}→ {'ok': True, 'text': ''}refused: no usage window and no cap flag
{} (claude)→ 5h 0% / weekly 0%refused: no five-hour or seven-day window
{'primary_window': {'reset_at': 1}}→ 5h 0%refused: primary_window.used_percent required
real chatgpt-plus-pro body→ weekly 22%weekly 22% (checked live)
real claude-pro-max body→ 5h 85% / weekly 42%identical (checked live)

That verdict is not decoration. _maybe_chatgpt_failover consults it, so the failure mode was the fleet sitting on an exhausted account behind a green tile with nothing written on it — and the claude side was worse than blank: 5h 0% / weekly 0% is a specific, plausible, wrong number. The validator refuses exactly the payloads that would have produced a confident all-clear and only those: an explicit limit_reached or allowed: false is evidence on its own and is still accepted with no window at all, so a real cap can never be turned into an error. extra='allow' throughout — the live Anthropic body carries eight keys nobody here has ever named, and refusing those would turn a vendor's routine addition into an outage.

The trap the new error path walked into. The first version reported a refused body with pydantic's own message, which names the field that broke. The ChatGPT payload's top-level field is literally rate_limit — and classify_failure() decides what a failure is by substring, with 'rate_limit' on its list. So "I no longer understand this body" was being reported to the operator as rate-limited: the precise misdiagnosis that function's own docstring says it was written to prevent ("the ChatGPT provider canary labelled a 404 as 'rate-limited', which sent diagnosis down the wrong path").

Caught by a test that asserted the label rather than the text. UsagePayloadError now carries a curated message and _shape_detail drops path elements that would mislabel it, keeping the ones that would not — so a broken nested field still reports as primary_window.used_percent: Field required and classifies as a plain error. Verified on the live box: classify_failure(...) -> ('error', 'error').

Worth generalising: when you introduce a new error string, check what the codebase's own classifier does with it. An error message is an input to something.

Two verbs instead of four private names

http_app/get_routes.py reached into this cluster's internals: it took srv._ssh_log_lock, read srv._ssh_log_cache, wrote srv._ssh_health_cache[key] directly and called srv._record_ssh_log. Re-exporting four private names to keep that working would have preserved a leak. Instead the module grew two public verbs and the routes shrank:

  • connection_log_rows(key) — a snapshot taken under the log lock. The route was iterating the live deque while the poll thread appended to it: a mutation-during-iteration race that would surface as an occasional 500 on a panel nobody is watching when it happens.
  • run_manual_test(cfg) — the Test button's whole sequence: probe, publish, journal as (manual test). A human pressing Test is asking a different question from the poll loop ("is it back yet"), so the answer deliberately bypasses the SSH_HEALTH_FAIL_THRESHOLD debounce. That was already true and now says so, with a test.

The injection bundles

ssh_checks takes no bundle at all. Nothing in it needs a collaborator from server.py — it shells out and the caches are its own. That is the whole reason the cluster was worth taking: a closed system with two outward-facing verbs and a roster.

provider_usage takes a frozen Collaborators holding LETTA_AGENTS and get_letta_id, built per call by server._provider_usage_deps(). LETTA_BASE_URL is imported from hosts.py instead, per rule 4: a dependency that already has its own home is imported, and injecting it would be ceremony.

What is re-exported, and what is not

Nine names in http_app/ and the startup banner were checked by grep before anything was dropped (rule 2). Six survive as re-exports (SSH_CONNECTIONS, SSH_HEALTH_POLL_INTERVAL, _ssh_poll_loop, cached_ssh_health, connection_log_rows, get_ssh_connection, plus run_manual_test under the route-facing name run_manual_ssh_test); the four private cache names do not, because the two new verbs replaced them. On the provider side only PROVIDER_USAGE_PROBES, _fetch_provider_oauth_creds and _probe_codex_usage come back — the failover cluster still in server.py calls all three.

Twenty-two now-dead names are asserted absent from server by parametrised tests, and every kept one is asserted to be the owning module's object. PROVIDER_USAGE_PROBES gets its own test proving it is the same dict the poll reads, because test_server.py patches it with monkeypatch.setitem — which only works on the module's own dict, not a copy.

Tests

105 new tests: 55 in tests/test_ssh_checks.py, 50 in tests/test_provider_usage.py, both pointed at the owning modules. The 15 superseded copies were deleted from tests/test_server.py and replaced with pointer comments. Suite: 2,756 → 2,846.

Beyond the moved assertions, the new files pin behaviour nothing covered before:

  • every payload the two models refuse, and the old code accepting each one — written out as the code that used to run, so the day the model stops earning its keep is visible;
  • a refused body is not labelled a rate limit, and a scrubbed path still leaves a noun in the message;
  • the peer-only entries (phone, Chromebook) are checked by tailscale, not ssh — losing that key would probe them with sshd they do not run and sit red forever;
  • the DERP-relayed box keeps a timeout several times the default, because 8s against a 43s round trip is two consecutive failures, i.e. "down";
  • the first failure is published when nothing is cached yet — a box already down at boot has no previous result to protect;
  • connection_log_rows returns a copy, not the live deque;
  • a threaded read against 50 poll cycles never yields a torn entry;
  • run_manual_test bypasses the debounce and marks its line manual;
  • the probe registry covers every provider type the fleet actually uses — a missing type is silently unprobed, which is a fleet nobody is watching;
  • and the bundle is rebuilt per call, proven by patching server.LETTA_AGENTS and watching the wrapper honour it.

A dead second implementation, left in place

dashboard/ssh_gateway.py is a ports-and-adapters version of ssh_test — SshTarget, ISshGateway, OpenSshGateway, ConfiguredIdentityStrategy — with its own 40-test file. Nothing in production imports it. It arrived on a merged feature branch and was never wired in.

It is not merely redundant, it is subtly wrong: ConfiguredIdentityStrategy returns the first identity file that exists on disk. That is exactly the bug ssh_test's docstring exists to describe — a key can exist and no longer be authorized (rotated, revoked), so stopping at the first file that exists wedges on a dead key forever even though a later one in the list still works.

Left in place rather than deleted, because deleting another agent's parallel work is not this round's call. But do not build on it, and if a future round wants the adapter shape, port the fallback chain into it first. There is a test in tests/test_ssh_checks.py naming this trap by name.

How to rank a cluster

The right question is: which names stay behind in server.py after the move? A name referenced only by the cluster travels with it and costs nothing. Counting every top-level name a cluster touches penalises exactly the clusters that are most self-contained. Run this from dashboard/ against the current file before choosing: 

import ast
from collections import defaultdict
src = open('server.py').read(); tree = ast.parse(src)
funcs = {n.name: n for n in tree.body
         if isinstance(n, (ast.FunctionDef, ast.AsyncFunctionDef))}
top = set(funcs)
for n in tree.body:
    if isinstance(n, ast.Assign):
        for t in n.targets:
            if isinstance(t, ast.Name): top.add(t.id)
refs = defaultdict(set)          # name -> top-level funcs that reference it
for fname, node in funcs.items():
    for sub in ast.walk(node):
        if isinstance(sub, ast.Name) and isinstance(sub.ctx, ast.Load) \
                and sub.id in top:
            refs[sub.id].add(fname)
def deps(name):
    n = funcs.get(name)
    return set() if n is None else {
        s.id for s in ast.walk(n)
        if isinstance(s, ast.Name) and isinstance(s.ctx, ast.Load) and s.id in top}
names = {...}                    # the cluster you are considering
while True:                      # pull in what only this cluster uses
    ext = set().union(*(deps(n) for n in names)) - names
    travels = {x for x in ext if not (refs[x] - names)}
    if not travels: break
    names |= travels
stays = sorted(set().union(*(deps(n) for n in names)) - names)
lines = sum(funcs[n].end_lineno - funcs[n].lineno + 1 for n in names if n in funcs)
print(lines, 'lines |', len(stays), 'stay behind:', stays)

Five caveats, all of them earned

  1. The script counts function bodies, so module-level constants that travel are free lines it does not credit — and the wrappers and explanatory comments left behind cost lines back. Round 9 measured 285 and removed 374, because SSH_CONNECTIONS is a 70-line literal the script cannot see. Round 8 measured 183 and removed 152. The error runs both ways; a big config literal in the set means you will beat the estimate.
  2. It cannot see http_app. It parses server.py and nothing else, so every srv.<name> call in the route ladders is invisible to it. Round 8 had seven such names, round 9 had nine. Always grep http_app/ for every name you plan to drop. The suite will not catch it: tests/http_app_harness.py stubs the service layer, so those tests pass against a name that no longer exists.
  3. A route reaching into a private name is a design signal, not just an import to preserve. Round 9's four were replaced by two verbs, and one of them turned out to be fixing a real race. Ask what the route is trying to do before you re-export the pieces it was doing it with.
  4. It cannot tell you a name is mis-clustered. Round 8 measured the "Document Vision health" section at 83 lines with zero names left behind — a mirage: that section is already extracted, and the 83 lines are the HEALTH_CHECKS registry and server_health, used by everything. Grep every name you are about to move.
  5. Cluster membership is a judgement — widen or narrow the set and the numbers move.

Standing rules for every round

  1. Extract lowest-residual-coupling first, measured with the script above, not by eye. Then grep every name in your set — the script cannot tell you a name is mis-clustered.
  2. Grep http_app/ before dropping any name. The script parses server.py only, and the route ladders reach in through srv.<name> at call time. The HTTP tests stub the service layer, so they will not catch a missing name either. Seven in round 8, nine in round 9.
  3. Point new tests at the owning module, never at server. A re-export is a second binding; the moved code closes over its own module global, so monkeypatch.setattr(server, 'X', …) isolates nothing while looking exactly like it does. This has bitten six rounds running — round 9's four connection_test patches in test_server.py were exactly this shape, and the pointer comment left in their place says so.
  4. Inject what stays behind in server.py rather than importing it, and resolve the bundle per call. Add a test that production wires the real collaborators, and one that proves the late binding. A dependency that already has its own module (LETTA_BASE_URL, mark_server_starting) is imported, not injected. And a cluster that needs no bundle is the best kind — look for those.
  5. Import back only what is still called. Assert the dropped names are absent so dead re-exports cannot creep back, and assert the kept ones are the owning module's object.
  6. A fake must be pinned to the real thing it fakes. Where a dashboard module fakes a rol_finances object, add one test that runs the path unpatched against the real one. (See the round-6 postscript.)
  7. Deploy and verify against the real thing. Committing is not deploying, and a 200 is not a verification. For a backend-only change, call the moved code on the live box and read the output. Round 8 found a feature that had never once worked because rc 127 and "nothing to report" render identically. If the moved code writes, find a reversible way to watch it write — and if there is no reversible way, say so in this file rather than firing it or pretending it was checked.
  8. Every Pydantic model dumps to a plain dict so browser-facing JSON stays byte-identical, and keep a golden-payload test against the prior literals — error strings included. Round 9 went further and ran the old classifier and the new one side by side against the live vendor bodies. Do that when you can; it is a five-line script and it converts "should be identical" into "is identical".
  9. Reach for Pydantic where a wrong value is silent, not everywhere. The test that proves it earns its keep is usually the one showing the old code accepting garbage — write that test as the old code, inline, so it keeps being true. And check the predicted defect is actually reachable: round 8's cache model was predicted for a torn read that could not happen and earned its place for an entirely different bug.
  10. An error message is an input to something. New in round 9. Before shipping a new failure string, run it through classify_failure() (or whatever downstream reads it) and assert the label, not the text. A message that names the vendor's own field can be read as a rate limit and swap the fleet's account.
  11. Stay out of js/ — unless the bug is there. A concurrent dashboard-boot.js refactor runs in parallel; an earlier round saw tests/test_project_plans.py fail on its edits, not ours. Confirm with git status js/ before blaming yourself. Round 9 touched nothing there.

Where Pydantic mattered, cumulatively

  • ModelStatSource.kind: Literal['codex','claude','gemini'] — a typo used to render a card with no windows and no error.
  • PcMonitor.memory_source: Literal['windows','linux'], frozen=True for the process-wide registry.
  • PcMetric derives alert from level as a property, so a new level can't be added without deciding whether it blinks the tab.
  • ProbeResult.hard — suppresses the Restart button for failures a restart can't fix; extra='forbid' catches misspelled flags.
  • HealthCacheEntry — the poller reassigns a whole entry rather than mutating fields, so a corrupt debounce record can't be read back into a later poll cycle.
  • PendingVendorReviewRow — pins the "pick a vendor" dialog's row shape so a renamed DB column fails at model construction, not as a blank cell.
  • ServerStatus — the four-state tab vocabulary, validated where a fifth state would silently escalate a healthy server as stale.
  • ReportRowClass — the only shape a cat-* class may have, checked at the one place that writes it into a report file on disk.
  • RecategorizeRequest — a row id must be a whole number and an amount must be finite, because int(3.9) and Decimal('nan') both used to succeed and then quietly do the wrong thing.
  • Win10CacheEntry — the entry, not the value, is the presence sentinel, so a cache whose legal answers include None can actually cache one.
  • ConversationMessages — the one message path that bypasses ILettaGateway, where an unrecognised payload used to become an empty tab indistinguishable from a quiet agent.
  • CodexUsage / ClaudeUsage (new) — the payload that decides whether the fleet's account gets swapped. An unreadable body used to classify as headroom; the claude side rendered it as a confident 5h 0% / weekly 0%. Now refused, and the refusal is deliberately worded so the dashboard does not call it a rate limit.

How this plan reaches the dashboard

It is already wired in: dashboard.html has a #dashboard-refactor-plan-frame iframe pointing at /notes_plans_handoffs/dashboard_refactor_plan.html, behind the Dashboard Refactor tab under Project Plans. Live at https://desktop-2obsqmc.tailb8fc54.ts.net/.

A trap that looks exactly like a failed deploy: a tab switch in the dashboard only toggles a CSS class, so the iframe is fetched once, when the dashboard page itself loads. A dashboard left open all day keeps showing whichever revision of this plan it pulled at load time, however many times you redeploy. The frame carries data-refresh-on-show, and activateView in js/boot/view-navigator.js re-fetches marked frames every time their tab is opened. If a plan still looks stale, reload the dashboard page before suspecting the deploy — and confirm with curl -s <live>/notes_plans_handoffs/<plan>.html | grep <marker>, which asks the server rather than the browser.
