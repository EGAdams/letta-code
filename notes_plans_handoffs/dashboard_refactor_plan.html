One user gesture that has to land in two places which can disagree: the expenses row in the finance database, and the cat-* class baked into the matching <tr> of a static report.html on disk. The undo has to repaint exactly the row the original write painted, by exactly the same matching rules. Split them and the two sides drift into disagreeing about which <tr> a transaction owns.

The undo journal's composition root travelled because this cluster is its only caller and its journal path is a constant nothing else reads. _get_category_taxonomy looks like it belongs but does not: three other call sites in server.py use it, so it stays behind and is injected.

Where the typing earned its keep

ReportRowClass — the class that goes into the file. _swap_cls repaints a row by dropping every class matching cat-[a-z0-9-]+ and prepending the new one. That strip pattern is the report file's real contract, but nothing checked the value going in against it. The class comes from the categories table's css_class column by way of the taxonomy — a plain untyped string out of a database — and went straight into a class="…" attribute in a file on disk.

A value with a space silently added a second class. One with a quote broke out of the attribute and corrupted a report nobody opens until a month-end review. And either one survives every later re-categorisation, because the strip cannot match it to take it back out. Now checked once, at the only place that writes, and a malformed class is refused without touching the file — a repaint that does not happen shows up as file_updated: false, and of the two outcomes only that one is recoverable. A test asserts the file's bytes are unchanged; another walks every css_class in the real seeded taxonomy and asserts the model accepts all 13.

RecategorizeRequest — the browser's payload. Two fields used to accept garbage in silence.

expense_id went through a bare int(), so a JSON 3.9 became expense 3 and true became expense 1 — a confident UPDATE against a real row that is not the one the user clicked.

signed_amount went through Decimal(), which accepts 'nan' and 'inf' without raising. WHERE amount='NaN' matches nothing, so the lookup fell through to the not-in-the-database branch and answered ok: true with "Transaction not in DB — color saved to report only": a success message, and a colour written to a report file, for a transaction that was never checked.

Amount parsing stays conditional exactly as the hand-rolled version was — with an expense_id in hand the row is found by id and signed_amount is display text that never reaches SQL. Error payloads are byte-identical to the strings they replace (Bad expense_id: 3.9, Bad amount: 'nan'), so the dialog sees what it always did.

The injection bundle, and why it is a bundle

Seven collaborators stay behind: _rol_get_connection, _resolve_reporting_category, _css_class_for_report_name, _find_matching_report_row, _report_file_for_url, _vendor_prefix, _get_category_taxonomy, plus the RECEIPT_ONLY_REPORT_PATH constant. Seven keyword arguments on three functions is noise, so they travel as one frozen Collaborators dataclass that server.py builds per call: 

def _recategorize_deps():
    return _recategorize.Collaborators(
        get_connection=lambda: _rol_get_connection(),
        resolve_reporting_category=_resolve_reporting_category,
        ...
    )

Per call is the whole point — build it at import and monkeypatch.setattr(server, '_rol_get_connection', …) lands on a name nothing calls any more, which is the trap that bit five earlier rounds. get_connection is a lambda rather than the function object because the undo service is a process-wide singleton that would otherwise freeze in whatever factory it saw first. test_server_wrapper_passes_the_real_collaborators asserts every entry is the real object, and test_server_wrapper_resolves_the_connection_at_call_time proves the late binding.

How to rank a cluster

The right question is: which names stay behind in server.py after the move? A name referenced only by the cluster travels with it and costs nothing. Counting every top-level name a cluster touches penalises exactly the clusters that are most self-contained. Run this from dashboard/ against the current file before choosing: 

import ast
from collections import defaultdict
src = open('server.py').read(); tree = ast.parse(src)
funcs = {n.name: n for n in tree.body
         if isinstance(n, (ast.FunctionDef, ast.AsyncFunctionDef))}
top = set(funcs)
for n in tree.body:
    if isinstance(n, ast.Assign):
        for t in n.targets:
            if isinstance(t, ast.Name): top.add(t.id)

refs = defaultdict(set)              # name -> top-level funcs that reference it
for fname, node in funcs.items():
    for sub in ast.walk(node):
        if isinstance(sub, ast.Name) and isinstance(sub.ctx, ast.Load) \
                and sub.id in top:
            refs[sub.id].add(fname)

names = {...}                        # the cluster you are considering
nodes = [funcs[n] for n in names if n in funcs]
lines = sum(n.end_lineno - n.lineno + 1 for n in nodes)
ext = {sub.id for n in nodes for sub in ast.walk(n)
       if isinstance(sub, ast.Name) and isinstance(sub.ctx, ast.Load)
       and sub.id in top and sub.id not in names}
stays   = sorted(x for x in ext if refs[x] - names)   # real coupling cost
travels = sorted(x for x in ext if not (refs[x] - names))
print(lines, 'lines |', len(stays), 'stay behind:', stays)
print('   travels with it:', travels)

Three caveats. The script counts function bodies, so module-level constants that travel are free lines it does not credit — round 7 measured at 332 and removed 297 net, because the wrappers and the explanatory comment left behind cost lines back. It also cannot tell you a name is mis-clustered: _get_category_taxonomy sat in the middle of the undo-journal block and looked like a member, but three unrelated call sites use it. Grep every name you are about to move before you cut. And cluster membership is a judgement — widen or narrow the set and the numbers move.

Standing rules for every round

  1. Extract lowest-residual-coupling first, measured with the script above, not by eye. Then grep every name in your set — the script cannot tell you a name is mis-clustered.
  2. Point new tests at the owning module, never at server. A re-export is a second binding; the moved code closes over its own module global, so monkeypatch.setattr(server, 'X', …) isolates nothing while looking exactly like it does. This has bitten five rounds running.
  3. Inject what stays behind rather than importing it, and resolve the bundle per call. Add a test that production wires the real collaborators.
  4. Import back only what is still called. Assert the dropped names are absent so dead re-exports cannot creep back.
  5. A fake must be pinned to the real thing it fakes. Where a dashboard module fakes a rol_finances object, add one test that runs the path unpatched against the real one — that boundary is sys.path-injected and entirely untyped, so nothing else is checking it. (See the round-6 postscript.)
  6. Every Pydantic model dumps to a plain dict so browser-facing JSON stays byte-identical, and keep a golden-payload test against the prior literals — error strings included.
  7. Reach for Pydantic where a wrong value is silent, not everywhere. The test that proves it earns its keep is usually the one showing the old code accepting garbage.
  8. Deploy and verify. Committing is not deploying. For a backend-only change, curl the endpoints that run the moved code — verify-live.sh only greps dashboard.html. If the moved code writes, find a reversible way to watch it write.
  9. Stay out of js/ — unless the bug is there. A concurrent dashboard-boot.js refactor runs in parallel; an earlier round saw tests/test_project_plans.py fail on its edits, not ours. Confirm with git status js/ before blaming yourself.
    Broken deliberately in e28bd5fd: the stale-plan bug lived in js/boot/view-navigator.js and could not be fixed anywhere else. git status js/ was clean first, the edit was one file, and bun test js/tests was run. Do the same if you have to go in: check, keep it to one file, run both suites.

Where Pydantic mattered, cumulatively

  • ModelStatSource.kind: Literal['codex','claude','gemini'] — a typo used to render a card with no windows and no error.
  • PcMonitor.memory_source: Literal['windows','linux'], frozen=True for the process-wide registry.
  • PcMetric derives alert from level as a property, so a new level can't be added without deciding whether it blinks the tab.
  • ProbeResult.hard — suppresses the Restart button for failures a restart can't fix; extra='forbid' catches misspelled flags.
  • HealthCacheEntry — the poller reassigns a whole entry rather than mutating fields, so a corrupt debounce record can't be read back into a later poll cycle.
  • PendingVendorReviewRow — pins the "pick a vendor" dialog's row shape so a renamed DB column fails at model construction, not as a blank cell.
  • ServerStatus — the four-state tab vocabulary, validated where a fifth state would silently escalate a healthy server as stale.
  • ReportRowClass (new) — the only shape a cat-* class may have, checked at the one place that writes it into a report file on disk.
  • RecategorizeRequest (new) — a row id must be a whole number and an amount must be finite, because int(3.9) and Decimal('nan') both used to succeed and then quietly do the wrong thing.

How this plan reaches the dashboard

It is already wired in: dashboard.html has a #dashboard-refactor-plan-frame iframe pointing at /notes_plans_handoffs/dashboard_refactor_plan.html, behind the Dashboard Refactor tab under Project Plans. Earlier revisions of this file claimed the opposite — that wiring it up was open housekeeping — and that claim was carried forward for several rounds without anyone checking dashboard.html. It is fixed here.

A related trap, because it looks exactly like a failed deploy: a tab switch in the dashboard only toggles a CSS class, so the iframe is fetched once, when the dashboard page itself loads. A dashboard left open all day keeps showing whichever revision of this plan it pulled at load time, however many times you redeploy. The frame now carries data-refresh-on-show, and activateView in js/boot/view-navigator.js re-fetches marked frames every time their tab is opened. If a plan still looks stale, reload the dashboard page before suspecting the deploy — and confirm with curl -s <live>/notes_plans_handoffs/<plan>.html | grep <marker>, which asks the server rather than the browser.
