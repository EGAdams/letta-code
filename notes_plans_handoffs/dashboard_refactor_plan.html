Where Pydantic mattered

Chosen specifically where a wrong value would otherwise be silent:

  • ModelStatSource.kind: Literal['codex','claude','gemini'] — a typo used to render a card with no windows and no error.
  • PcMonitor.memory_source: Literal['windows','linux'], frozen=True for the process-wide registry.
  • PcMetric derives alert from level as a property, so a new level can't be added without deciding whether it blinks the tab.
  • ProbeResult.hard — suppresses the Restart button for failures a restart can't fix; extra='forbid' catches misspelled flags.
  • HealthCacheEntry (new) — the poller reassigns a whole entry rather than mutating fields, so a corrupt debounce record can never be read back into a subsequent poll cycle.
  • PendingVendorReviewRow (new) — pins the "pick a vendor" dialog's row shape so a renamed DB column fails at model construction, not as a blank cell in the dialog.

Findings worth stating plainly

The patch-target trap — hit four times.

server.py re-exports moved names, but a re-export is a second binding: the moved code closes over its own module global. Tests doing monkeypatch.setattr(server, 'X', ...) isolated nothing while looking exactly like they did.

  • 18 model-stats tests were running the real extractor against a live OAuth account.
  • The usage-history fixture was aimed at the real, live history file.
  • Six frita tests stubbed server._probe_sdk_status, which health/frita.py doesn't read — they passed while talking to the live executor on :8799, and would have kept passing with the probe logic deleted.
  • The vendor-review extraction hit it on the first draft, before any test ran against live data: finance/vendor_review.py initially imported its own _vendor_category_lookup directly, which would have made test_server.py's existing monkeypatch.setattr(server, '_vendor_category_lookup', ...) calls silently ineffective. Caught in review and fixed by injecting the lookup as a parameter before it ever ran against the real vendor_category.yaml.

All repointed to the owning modules or fixed via injection. Each is now demonstrated by a dedicated test class, not just described in a comment.

A real break, caught by the new tests.

_model_usage_sample_loop referenced MODEL_STAT_SOURCES without importing it. The background sampler thread would have died at boot with a NameError, leaving the leak detector blind except for moments someone happened to have the tab open. Fixed and confirmed alive in production.

Three of my own test assertions were wrong, not the code.

\x0b/\x0c alone are rejected as “empty” rather than “control characters”, because str.strip() treats them as whitespace — split into two tests. A source-text assertion ('bypassPermissions' not in src) failed because the explanatory comment contains the word; rewritten to assert on the actual argv instead.

tests/test_project_plans.py briefly failed on dashboard-boot.js contents. Confirmed via git status js/ that this was the concurrent dashboard-boot.js refactor running in parallel, not this work — it passed again on the next full run. This refactor stayed entirely inside Python plus http_app/get_routes.py for that reason; nothing under js/ was touched.
