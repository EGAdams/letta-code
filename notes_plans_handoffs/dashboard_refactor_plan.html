Where the typing earned its keep

A four-word vocabulary that nothing was checking.

track_down_duration branched on a bare status in ('up', 'starting'). compute_server_status emits four states. A fifth state added there, a rename, or a stray 'Up' would fall through to the down branch and start a stale clock on a healthy server — which escalates the tab ten minutes later with nothing in the UI to point at. Now a ServerStatus Literal validated at the call, plus TestServerStatusVocabulary, which drives compute_server_status through all five of its branches and asserts the set it produces is exactly the set the Literal accepts. If someone adds a fifth state, that test fails before the silent escalation ever ships.

log_activity_health now answers with ProbeResult.

It built {'ok':…, 'text':…} by hand while health/probe.py already named that contract. A log mtime standing in for a health check should be indistinguishable from one, so it goes through probe() like every other check. Payload is byte-identical; a test asserts the key set matches a real probe's.

Patch-target trap — designed out this time, not caught late

server_log_rows needs cached_server_health and server_status_kind, both of which stay in server.py. Importing them would be a cycle; binding them at import time would have detached the module from monkeypatch.setattr(server, 'cached_server_health', …) — the exact trap that bit the previous four extractions. So they are arguments: 

def server_log_rows(cfg, q='', *, health_reader, status_kind, starting_window):

The server.py wrapper resolves all three at call time, which keeps the existing patch target working, and TestServerWiring.test_wrapper_passes_the_real_collaborators covers the wiring — injection is only honest if something checks that production passes the real objects.

Dead re-exports are how the trap gets set for the next person.

Only names server.py or a srv. route still calls are imported back: log_activity_health, _trim_log_cache, the four lifecycle functions, and _starting_servers/_starting_lock by identity (tests/test_server.py's _clear_starting() resets the one real registry through server; a rebind would hand it a second, empty dict). tail_lines, _format_age, SERVER_LOG_TAIL, LOG_ACTIVITY_WINDOW, _server_down_since and SERVER_STALE_DOWN_SECONDS were dropped, and two tests assert they are absent (assert not hasattr(server, …)) so a well-meaning re-export cannot creep back and start drifting from the real definition.

How to rank a cluster — the old numbers were measured wrong

The previous ranking counted every server.py top-level name a cluster referenced as "external". That counts a cluster's own module-level state against it — and it penalised precisely the clusters that were most self-contained. win10-node was listed at 9 external names; 13 of the names it touches are its own WIN10_* constants and _win10_* caches, which travel with it. Its real residual coupling is 2.

The right question is: which names stay behind in server.py after the move? A name referenced only by the cluster travels with it and costs nothing. Run this from dashboard/ against the current file before choosing: 

import ast
from collections import defaultdict
src = open('server.py').read(); tree = ast.parse(src)
funcs = {n.name: n for n in tree.body
         if isinstance(n, (ast.FunctionDef, ast.AsyncFunctionDef))}
top = set(funcs)
for n in tree.body:
    if isinstance(n, ast.Assign):
        for t in n.targets:
            if isinstance(t, ast.Name): top.add(t.id)

refs = defaultdict(set)              # name -> top-level funcs that reference it
for fname, node in funcs.items():
    for sub in ast.walk(node):
        if isinstance(sub, ast.Name) and isinstance(sub.ctx, ast.Load) \
                and sub.id in top:
            refs[sub.id].add(fname)

names = {...}                        # the cluster you are considering
nodes = [funcs[n] for n in names if n in funcs]
lines = sum(n.end_lineno - n.lineno + 1 for n in nodes)
ext = {sub.id for n in nodes for sub in ast.walk(n)
       if isinstance(sub, ast.Name) and isinstance(sub.ctx, ast.Load)
       and sub.id in top and sub.id not in names}
stays   = sorted(x for x in ext if refs[x] - names)   # real coupling cost
travels = sorted(x for x in ext if not (refs[x] - names))
print(lines, 'lines |', len(stays), 'stay behind:', stays)
print('   travels with it:', travels)

Two caveats. The script counts function bodies, so module-level constants that travel are free lines it does not credit. And cluster membership is a judgement — the sets below are the ones measured on 1351c3cc; widen or narrow them and the numbers move (that is why several line counts differ from the previous table).

Standing rules for every round

  • Extract lowest-residual-coupling first, measured with the script above, not by eye.
  • Point new tests at the owning module, never at server. A re-export is a second binding; the moved code closes over its own module global, so monkeypatch.setattr(server, 'X', …) isolates nothing while looking exactly like it does. This has bitten five rounds running.
  • Inject what stays behind rather than importing it. It breaks the cycle and it preserves the existing patch target — and add a test that production wires the real collaborators.
  • Import back only what is still called. Assert the dropped names are absent so dead re-exports cannot creep back.
  • Every Pydantic model dumps to a plain dict so browser-facing JSON stays byte-identical, and keep a golden-payload test against the prior literals.
  • Reach for Pydantic where a wrong value is silent, not everywhere. The test that proves it earns its keep is usually the one showing the old code accepting garbage.
  • Deploy and verify. Committing is not deploying. For a backend-only change, curl the endpoints that run the moved code — verify-live.sh only greps dashboard.html.
  • Stay out of js/. A concurrent dashboard-boot.js refactor runs in parallel; an earlier round saw tests/test_project_plans.py fail on its edits, not ours. Confirm with git status js/ before blaming yourself.

Where Pydantic mattered, cumulatively

  • ModelStatSource.kind: Literal['codex','claude','gemini'] — a typo used to render a card with no windows and no error.
  • PcMonitor.memory_source: Literal['windows','linux'], frozen=True for the process-wide registry.
  • PcMetric derives alert from level as a property, so a new level can't be added without deciding whether it blinks the tab.
  • ProbeResult.hard — suppresses the Restart button for failures a restart can't fix; extra='forbid' catches misspelled flags.
  • HealthCacheEntry — the poller reassigns a whole entry rather than mutating fields, so a corrupt debounce record can't be read back into a later poll cycle.
  • PendingVendorReviewRow — pins the "pick a vendor" dialog's row shape so a renamed DB column fails at model construction, not as a blank cell.
  • ServerStatus (new) — the four-state tab vocabulary, validated where a fifth state would silently escalate a healthy server as stale.
